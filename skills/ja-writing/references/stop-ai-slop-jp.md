# stop-ai-slop-jp 蒸留版

AI で書いた日本語を「人間が書いた文章に戻す」ための Claude Skill (作者 Daichi Nagashima、MIT、v0.1.1)。SKILL.md 1 本 (大原則・コアルール 14 項・クイックチェック・5 軸採点・修正の優先順位) と references 3 本 (構造 6 系統 / 語彙 8 系統 / 対比例 17 本) から成る。**この蒸留版の役割は、姉妹スキル `avoid-ai-slop-ja` の出所を辿れるようにすること**。ここでは原典の分類と各パターンの理由を索引する。`avoid-ai-slop-ja` のどこが原典由来でどこが独自かの対応表は、原典ではなく `avoid-ai-slop-ja` 側の変更で古くなるので `../MAPPING.md` に分けてある。

## まず押さえる

1. **大原則は「AI 臭の正体は書き手の不在」**。全角ダッシュや偏愛語は表面の症状にすぎない。書く前と後に 3 問を自分に問う: 自分は何を「○○だ」と引き受けているか / 誰かが反論できる具体的な主張があるか / 同じテーマの平均的な記事とどこで違うか。答えられないなら表面修正は後回しで、先に言いたいことを決める (SKILL.md § 大原則)。README も「本 Skills は書き手の不在については修正できない」と限界を明記している (README.md § AI Slopとは)。

2. **コアルールは 14 項で 3 群**。A. 主体と立場 (最優先、1〜6): false agency を潰す / 反証可能な主張 / 強度を一段下げ中間温度を混ぜる / 伝聞を残す / 遠くから語らない / 両論併記を捨て毒を許す。B. 構造 (7〜10): 命題型 H2 / 二項対比 / ムラ / 3 項目並列。C. 語彙と記号 (11〜14): 偏愛語・必殺技造語・副詞 / 横文字メタファー / 形容詞や心情に「」を使わない / 記号アーティファクト (SKILL.md § コアルール)。

3. **修正の優先順位は 立場 → false agency → 構造のテンプレ → 語彙とフレーズ → 記号**。「1 と 2 を直さず 5 だけ直しても、AI 臭は残る」。README の使い方節も同じ順を繰り返す (SKILL.md § 修正の優先順位、README.md § 使い方)。

4. **採点は 5 軸 (立場 / リズム / 主体性 / 具体性 / 削減) 各 1〜10、合計 35/50 未満なら書き直す**。原典の採点は合否線だけで、35 以上の扱いや採点例は書いていない (SKILL.md § 採点)。

5. **クイックチェックは 5 層・計 35 項**: 構造 6 / 文・段落 7 / 記号 6 / 語彙 9 / 強度と立場 7。冒頭で「何より音読が効く」とし、黙読でも息が続かない箇所・読点を打ちたい箇所・リズムが揃いすぎた箇所を見る (SKILL.md § クイックチェック)。

6. **false agency は「AI 臭の構造的な核心」**。無生物が能動動詞を取ったら「誰が」を主語に立て直す (11 対の対応表)。「誰が」が思いつかないなら書き手がその話を持っていない。翻訳調動詞 (指している / 示している / 収斂する) はこの主体隠しの語彙的な現れ、体験に「設計」「装置」を当てるのも同類 (references/structures.md § 1-1・1-2、references/phrases.md § 2)。

7. **系統 5 (立場から逃げる) と系統 6 (無害さチューニング) は原因で分けている**。5 は「間違えない」デフォルトでプロンプトと書き手の意識で直せる。6 は RLHF の「公平であれ・両論併記しろ」の漏れで、モデル側のクセなので**書き手が手で書き足すしかない箇所が多い** (毒・自虐・皮肉)。ただし「全部毒舌」も別の臭さで、必要な箇所に必要なだけ (references/structures.md § 5・6)。

8. **語彙は「撒くな」であって全消しではない**。phrases.md 冒頭が「どの語も 1〜2 回なら自然で、1 記事に頻出すると臭う」と明言し、項目ごとに頻度上限を置く: 副詞は 1 段落 2 個以上で NG、「○○すぎる」は 1 記事 2〜3 回まで、(笑) は 1 記事 1〜2 回、比喩テンプレは 3 回以上で臭う、ヘッジは 1 段落 1 つまで、装飾絵文字は 5〜6 個で臭い残すなら 1〜2 個 (references/phrases.md 各節)。保留 disclaimer の 1 記事 1〜2 回は structures.md § 5-2 にある。

9. **記号アーティファクトは原因が機械処理側なので「検索 → 全置換」で潰す**。対象は `**` 残骸、コロン後の半角スペース、全角文字に紛れた半角スペース、全角ダッシュ (→ コロン・改行・読点)、装飾絵文字の均等撒布。SKILL.md ではこれに中黒並列 A・B・C (→「と」「や」) と、固有名詞・直接引用以外の「」を加える (references/phrases.md § 8、SKILL.md ルール 13・14)。

10. **ムラは 5 種**: 長さ / 密度 / トーン / 結論 / 詳細度。加えて段落の均一な閉じ方、体験→引用→抽象化テンプレの 3 連続、文末語尾の揺れの消失、**不完全さ (誤字・言い淀み) の不在**を系統 4 に置く。原典は「完璧であることそのものが AI 臭の指紋」とし、言い淀みや小さなブレを後から AI に消させないことを許す (references/structures.md § 4)。

11. **伝聞は事実の書き方の規則**。調べた事実には「らしい」「そうです」「ようだ」「と聞いた」を混ぜ、直接体験・既知のことは断定でよい。Wikipedia/辞書型の一文圧縮を崩す処方とセット (references/structures.md § 3-3、references/examples.md 例 3)。

12. **対比例 17 本の「人間版」は「修正の発想を盗むためのサンプル。正解として丸暗記しない」**。各例は AI 版 / 人間版 / 修正点で組み、17 例中 11 例は「含まれる AI 臭」の節も持つ (例 4・5・6・8・12・13 には無い)。冒頭に structures.md か phrases.md の該当節へのポインタが付く (references/examples.md 冒頭)。

13. **原典は想定ジャンルを明記していない** (README は「AIで下書きした日本語を、公開前にレビュー・修正する」とだけ書く)。例の題材は技術ブログ・体験記・レビュー記事など個人記事が中心 (examples.md の見出し)。文書種別 (ブリーフィング・法務・技術ドキュメント) による使い分けの規定は無い。README の使い方はレビューのみ / 書き換え / 下書きから / 公開前チェックの 4 プロンプト例 (README.md § 使い方)。

14. **英語原典 hardikpandya/stop-slop との関係**: frontmatter の `inspired-by: hardikpandya/stop-slop`、README の「日本語版です」「着想元」、CHANGELOG 0.1.0 の「元ネタ: 構造とフロントマター形式」。日本語パターンの分類と実例は別の元ネタ (note「その文章、AIに書かせただろ」) から来ている。structures.md は英語圏の型名を併記する (Not X. It's Y. / telegraphed reversal / negative listing / dramatic fragmentation / narrator-from-a-distance / throat-clearing / vague declaratives)。stop-slop 側の中身との差分はこの clone からは確認できない。

## 構造 6 系統と語彙 8 系統の分類

構造は「それぞれが生む偽物」で束ねた 6 系統 (references/structures.md 冒頭)。語彙は 8 系統 (references/phrases.md 冒頭)。

| 構造系統 | 下位パターン | 原典が挙げる理由 |
|---|---|---|
| 1. 主体を消す | 1-1 false agency / 1-2 体験の壮大化 (+ 必殺技造語) / 1-3 一人称の消失と一般論 | 人間の文では誰かが何かをしている。AI の文では概念が勝手に動く。一般論だけの段落は情報量ゼロに近い |
| 2. ドラマを偽造する | 2-1 二項対比 / 2-2 否定的列挙 / 2-3 劇的な断片化 | 平坦な内容に構文で起伏を付ける。直接言い切れば済むことを回り道する |
| 3. 英語ブログの骨格を直輸入 | 3-1 命題型 H2 (+ H2 の言い換えで本文を始める悪化版) / 3-2 決めつけ開幕 / 3-3 一文圧縮 / 3-4 メタ構造宣言 / 3-5 ❌/✅ 比較 | 型は機能的だが日本語の運びと衝突して翻訳調になる。命題型 H2 は各節を小さな TED talk にする。人間は控えめから始めて確信に至り、AI は断言から始めて控えめになる |
| 4. リズムを均す | 4-1 ムラ 5 種 / 4-2 段落の均一な閉じ方 / 4-3 体験→引用→抽象化の反復 / 4-4 3 項目並列 / 4-5 文末の揺れ不足 / 4-6 不完全さの不在 | 均一さは「疲れていない・迷っていない・関心の濃淡がない」ことを意味し、機械的に感じさせる根本 |
| 5. 立場から逃げる | 5-1 中間温度の欠如 / 5-2 リチュアル化した disclaimer / 5-3 遠くから語る話者 | AI のデフォルトは「間違えないこと」。「AI 臭の本体に最も近い系統」 |
| 6. 無害さにチューニング | 6-1 全方位肯定 / 6-2 毒・皮肉・自虐・罵倒の不在 | RLHF のお行儀の良さの漏れ。両論併記は判断材料の提供に見えて判断の放棄 |

| 語彙系統 | 中身 | 理由 / 上限 |
|---|---|---|
| 1. 定型句と偏愛語 | 表層の定型句 / 偏愛語 (質感・認知・評価・抽象比喩・思想語の 5 群) / 必殺技造語 / 比喩テンプレ | 偏愛語は具体性を装った抽象語で「いまの臭いの中心」。必殺技造語は文芸文体の学習の副作用 |
| 2. 翻訳調 | 翻訳調動詞 / アカデミック自称 (本稿・本記事・筆者) | point to / suggest / emerge の直訳で主体を抽象化する |
| 3. 英語ネイティブ思考の漏れ | 横文字メタファー / 過剰なカタカナ (表 9 語) / 英語固有名詞の律儀さ | 技術用語はカタカナのままでよい。フル正式名称が 3 つ並んだら警戒 |
| 4. 立場を薄める語 | 結論回避 / 三段ヘッジ / 曖昧な断言 / 弱い否定 / 強い評価+根拠なし | 曖昧な断言は「何が・なぜ」を書けなければ削る。弱い否定は「やるな」と言い切る |
| 5. 時間稼ぎと自己解説 | 咳払いの前置き / メタコメント | 削除して直接本題に入る |
| 6. 強度の振り切り | 根拠なし副詞 / 「○○すぎる」連発 / (笑) | 中間温度の欠如の語彙版 |
| 7. ビジネスジャーゴン | コミット / レバレッジ / ディープダイブ等 8 対 | 横文字メタファーと並走して撒かれる |
| 8. 機械的なアーティファクト | `**` / `: ` / 全角に紛れた半角スペース / ── / 装飾絵文字 | 出力処理の痕跡。賢くないモデルほど絵文字が顕著 |
